# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal learning workspace for LangChain 1.2 and LLM APIs, organized into one directory per chapter (`chapter01_summary/`, `chapter02_models/`, ...). There is no package, build system, test suite, or linter config; dependencies are pinned in `requirements.txt`. Each file is a standalone script meant to be run directly.

`main.py` at the root is the unused PyCharm template stub.

## Environment

- Python interpreter: the conda env `langchain1.2` (`~/miniconda3/envs/langchain1.2`), as configured in `.idea/misc.xml`. Activate it with `conda activate langchain1.2` before running anything.
- Install dependencies with `pip install -r requirements.txt`. It pins the whole course stack (LangGraph, MCP, providers, web, etc.), not just what the current scripts import, including the RAG / document-parsing block at the bottom (Milvus, transformers, CPU torch, unstructured). When adding a package, add it to the matching section with a pinned version.
- LLM calls go through LangChain chat models (`init_chat_model`) to one of two backends, chosen by `LLM_PROVIDER`: `dashscope` (Alibaba Cloud Model Studio / Qwen, the default) or `ollama` (local server). Not to OpenAI.
- `common/llm.py` owns provider selection. Scripts call `get_chat_model(thinking=True)` and `reasoning_text(chunk)` instead of building models or reading provider env vars themselves. DashScope uses `ChatDeepSeek` pointed at its OpenAI-compatible endpoint (plain `ChatOpenAI` drops `reasoning_content`) with `extra_body={"enable_thinking": ...}`; Ollama uses `ChatOllama` with `reasoning=...` against the native API, so `OLLAMA_BASE_URL` has no `/v1`. Both put streamed thinking text in `chunk.additional_kwargs["reasoning_content"]`.
- Config comes from env vars, loaded by `common/llm.py` with `load_dotenv()` from a gitignored `.env` at the repo root (keys in `.env.example`: `LLM_PROVIDER`, `DASHSCOPE_API_KEY`/`DASHSCOPE_BASE_URL`/`DASHSCOPE_MODEL`, `OLLAMA_BASE_URL`/`OLLAMA_MODEL`). Real OS env vars take precedence over `.env`. Never hardcode keys in scripts; when adding a new variable, add it to both `.env` and `.env.example`.

## Running

Run scripts as modules from the repo root so `common` is importable (`python chapter02_models/init_chat_model.py` fails with `ModuleNotFoundError`):

```bash
conda activate langchain1.2
python -m chapter02_models.init_chat_model
LLM_PROVIDER=ollama python -m chapter02_models.init_chat_model
```

`chapter02_models/init_chat_model.py` streams a thinking model's response with `model.stream()`, printing the reasoning first and then `chunk.content`. `chapter01_summary/openai_sdk.py` is the raw OpenAI-SDK DashScope example, kept for comparison. `chapter03_langsmith/` holds LangSmith tracing demos (`LANGSMITH_*` vars in `.env`): `init_chat_model.py` is a copy of the chapter02 demo, and `chat_openai.py` streams through plain `ChatOpenAI`, so it prints no reasoning. `chapter04_prompt_template/chat_prompt_template.py` builds the prompt with `ChatPromptTemplate` and streams it the same way. `chapter05_tools/chat_prompt_template.py` binds a `get_weather` tool with `bind_tools`, runs the tool calls the model requests, and sends the results back for a final answer. It keeps the conversation in `prompt_value.to_messages()`, because the raw `messages` list still contains the unfilled `{placeholders}`. `chapter06_structured_output/structured_output.py` wraps the model with `with_structured_output(MovieModel, include_raw=True)` (a Pydantic model), so `invoke()` returns a dict with `raw` (the `AIMessage`), `parsed` (the `MovieModel`) and `parsing_error`, which it prints with `rich`. It sends a plain tuple list, not a template, so the `{name}` in its system message reaches the model literally. `chapter07_agents/agent.py` defines `SmartAgent`, a `create_agent` agent with `get_weather`, `check_stock` and `multiply` (fake results). It keeps no checkpointer: `chat()` appends the user turn to `self.messages`, invokes with the whole list, and stores `result["messages"]` back, so tool calls stay in the history and follow-ups like "multiply the last result by 2" work; `reset()` empties the list. Its `main()` runs four scripted questions, then resets and shows the agent has forgotten. `chapter07_agents/interactive_loop_agent.py` imports `SmartAgent` and chats in the terminal (`reset` clears history, `exit`/`quit` or Ctrl-D/Ctrl-C ends). `chapter08_middleware/summarization.py` adds `SummarizationMiddleware` to an agent: the default model chats, while `get_summary_model()` (DashScope `DASHSCOPE_SUMMARY_MODEL`, a flash model, thinking off) writes the summary. Its triggers are tiny on purpose (6 messages, 100 tokens, or 0.001 of `max_input_tokens`). The `fraction` trigger reads `max_input_tokens` from the summary model's `profile`, so the script passes `profile={"max_input_tokens": 128000}`. It keeps the last 3 messages (the last history turn plus the new question), so the first 4 of the 6 history messages get summarised. `chapter08_middleware/human_in_the_loop.py` adds `HumanInTheLoopMiddleware`: every tool call pauses for review, and `check_stock` (an `InterruptOnConfig`, so PyCharm type-checks it against the `TypedDict`) allows only approve/reject. The agent has an `InMemorySaver` checkpointer and `SmartAgent.config` carries a `thread_id`, so `chat()` sends only the new message, loops on `result["__interrupt__"]`, and resumes with `Command(resume={"decisions": [...]})`, one decision per pending tool call. `history()` reads the thread's messages from `get_state()`, and `reset()` switches to a new `thread_id`. `ask_human()` reads decisions from stdin, so pipe answers in to run it non-interactively. `chapter08_middleware/pii.py` stacks `PIIMiddleware` rules with `apply_to_input=True` (email `redact`, credit_card `mask`, url `hash`, mac_address `mask`, ip `block`) and pretty-prints the conversation to show the rewritten input. The built-in detectors only match a Luhn-valid card number and a 6-group MAC address, so keep test inputs valid. `block` raises `PIIDetectionError` instead of rewriting; the input contains `192.168.1.1`, so the run stops before the model call and the script catches the error and prints `e.pii_type` and `e.matches`. Remove the IP line to see the redacted conversation instead. `chapter08_middleware/model_fall_back.py` adds `ModelFallbackMiddleware(get_summary_model())`, which retries a failed model call with each fallback in order and swallows the primary's error. To force the fallback, the primary is `get_chat_model().model_copy(update={"model_name": "no-such-model"})`, and the script prints the reply's `response_metadata["model_name"]` (the summary model). That field is `model` on `ChatOllama`, so under `LLM_PROVIDER=ollama` the primary succeeds and the fallback never runs. `chapter08_middleware/to_do_list.py` adds `TodoListMiddleware` (a `write_todos` tool, list kept in `state["todos"]`) to an agent with `get_weather`, `check_stock` and `multiply`. The middleware's built-in prompt discourages todos for simple requests, so the system prompt tells the agent to write the list first and update it after each step. The script prints the messages and then `response["todos"]`. In practice the agent updates the list once per model turn (three `write_todos` calls for the three steps, run alongside the other tool calls) and may mark several items `in_progress` at once, since the middleware doesn't enforce one at a time. `chapter08_middleware/tool_retry.py` adds `ToolRetryMiddleware(retry_on=(TimeoutError,), max_retries=3, ...)` to an agent whose fake `check_weather` tool raises `TimeoutError` on its first two calls (a module-level `attempts` counter), so the third call succeeds. The retries happen inside the one tool call, so the output shows a single `ToolMessage` and the model never sees the errors; `on_failure="continue"` would return the final error to the model as a `ToolMessage` if all retries failed. `chapter08_middleware/model_retry.py` adds `ModelRetryMiddleware(max_retries=2, retry_on=should_retry, ...)` to an agent whose model is the `no-such-model` copy, so all three calls fail with `NotFoundError`. `should_retry` is a callable `retry_on` that prints each failure and returns `True`. With `on_failure="continue"` the run ends with an `AIMessage` holding the error instead of raising. Like the fallback demo, under `LLM_PROVIDER=ollama` the fake name has no effect and the call succeeds. `chapter08_middleware/filesystem_file_search.py` adds `FilesystemFileSearchMiddleware`, which supplies `glob_search` and `grep_search` tools (so `tools=[]`) confined to `root_path`, with paths shown relative to it. `root_path` is the repo root built from `__file__`: `Path` resolves a relative path such as `"../"` against the working directory, which with `python -m` is the repo root, so `"../"` would search its parent. The agent is asked which files define `multiply`. `chapter09_memory/short_term_in_memory.py` gives a tool-less agent an `InMemorySaver` checkpointer and invokes it twice with the same `thread_id`, sending only the new message each time; the second question ("我是谁？") is answered from the first turn. Each `response["messages"]` is the whole thread, so the second printout repeats the first turn. `chapter09_memory/long_term_in_memory.py` gives an agent an `InMemoryStore` (`store=`) and a `CustomState` (an `AgentState` subclass adding `user_id`), passed as `state_schema`. `save_user_info` and `get_user_info` reach the store through an injected `ToolRuntime` (left out of the tool schema), using namespace `("users",)` and key `runtime.state["user_id"]`, so every `invoke` must pass `user_id` in its input. There is no checkpointer, so each of the three invokes starts with no history: "我是Michael" saves the name for `user_1`, a new conversation with `user_1` recalls it via `get_user_info`, and `user_2` gets `user info not found`; the script then prints `store.search(("users",))`. `create_agent` carries `# noinspection PyTypeChecker` because PyCharm wrongly reports that `CustomState` isn't assignable to `type[AgentState]` (it misreads the inherited `jump_to` qualifier); don't redeclare `jump_to` to silence it. `chapter10_RAG/text_loader.py` loads `asset/load/text.txt` (the folder of sample files for loaders) with `TextLoader(encoding="utf-8")` and prints the single `Document`'s type, `metadata` (`source` only) and `page_content`. Like `filesystem_file_search.py`, it builds the path from `__file__`, since a relative `"../"` path resolves against the working directory. `chapter10_RAG/csv_loader.py` loads `asset/load/users.csv` with `CSVLoader` the same way and prints each of the 4 `Document`s: one per row, `page_content` as `column: value` lines, `metadata` with `source` and `row`.
