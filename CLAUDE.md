# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal learning workspace for LangChain 1.2 and LLM APIs, organized into one directory per chapter (`chapter01_summary/`, `chapter02_models/`, ...). There is no package, build system, test suite, or linter config; dependencies are pinned in `requirements.txt`. Each file is a standalone script meant to be run directly.

`main.py` at the root is the unused PyCharm template stub.

## Environment

- Python interpreter: the conda env `langchain1.2` (`~/miniconda3/envs/langchain1.2`), as configured in `.idea/misc.xml`. Activate it with `conda activate langchain1.2` before running anything.
- Install dependencies with `pip install -r requirements.txt`. It pins the whole course stack (LangGraph, MCP, providers, web, etc.), not just what the current scripts import; the RAG / document-parsing block at the bottom is commented out until those chapters. When adding a package, add it to the matching section with a pinned version.
- LLM calls go through LangChain chat models (`init_chat_model`) to one of two backends, chosen by `LLM_PROVIDER`: `dashscope` (Alibaba Cloud Model Studio / Qwen, the default) or `ollama` (local server). Not to OpenAI.
- `common/llm.py` owns provider selection. Scripts call `get_chat_model(thinking=True)` and `reasoning_text(chunk)` instead of building models or reading provider env vars themselves. DashScope uses `ChatDeepSeek` pointed at its OpenAI-compatible endpoint (plain `ChatOpenAI` drops `reasoning_content`) with `extra_body={"enable_thinking": ...}`; Ollama uses `ChatOllama` with `reasoning=...` against the native API, so `OLLAMA_BASE_URL` has no `/v1`. Both put streamed thinking text in `chunk.additional_kwargs["reasoning_content"]`.
- Config comes from env vars, loaded by `common/llm.py` with `load_dotenv()` from a gitignored `.env` at the repo root (keys in `.env.example`: `LLM_PROVIDER`, `DASHSCOPE_API_KEY`/`DASHSCOPE_BASE_URL`/`DASHSCOPE_MODEL`, `OLLAMA_BASE_URL`/`OLLAMA_MODEL`). Real OS env vars take precedence over `.env`. Never hardcode keys in scripts; when adding a new variable, add it to both `.env` and `.env.example`.

## Running

Run scripts as modules from the repo root so `common` is importable (`python chapter02_models/test.py` fails with `ModuleNotFoundError`):

```bash
conda activate langchain1.2
python -m chapter02_models.test
LLM_PROVIDER=ollama python -m chapter02_models.test
```

Despite its name, `chapter02_models/test.py` is a demo script, not a pytest test. It streams a thinking model's response with `model.stream()`, printing the reasoning first and then `chunk.content`. `chapter01_summary/test_0.py` is the raw OpenAI-SDK DashScope example, kept for comparison. `chapter03_langsmith/` holds LangSmith tracing demos (`LANGSMITH_*` vars in `.env`): `init_chat_model.py` is a copy of the chapter02 demo, and `chat_openai.py` streams through plain `ChatOpenAI`, so it prints no reasoning. `chapter04_prompt_template/chat_prompt_template.py` builds the prompt with `ChatPromptTemplate` and streams it the same way. `chapter05_tools/chat_prompt_template.py` binds a `get_weather` tool with `bind_tools`, runs the tool calls the model requests, and sends the results back for a final answer. It keeps the conversation in `prompt_value.to_messages()`, because the raw `messages` list still contains the unfilled `{placeholders}`. `chapter06_structured_output/structured_output.py` wraps the model with `with_structured_output(MovieModel, include_raw=True)` (a Pydantic model), so `invoke()` returns a dict with `raw` (the `AIMessage`), `parsed` (the `MovieModel`) and `parsing_error`, which it prints with `rich`. It sends a plain tuple list, not a template, so the `{name}` in its system message reaches the model literally. `chapter08_middleware/summarization.py` adds `SummarizationMiddleware` to an agent: the default model chats, while `get_summary_model()` (DashScope `DASHSCOPE_SUMMARY_MODEL`, a flash model, thinking off) writes the summary. Its triggers are tiny on purpose (6 messages, 100 tokens, or 0.001 of `max_input_tokens`). The `fraction` trigger reads `max_input_tokens` from the summary model's `profile`, so the script passes `profile={"max_input_tokens": 128000}`. It keeps the last 3 messages (the last history turn plus the new question), so the first 4 of the 6 history messages get summarised. `chapter08_middleware/human_in_the_loop.py` adds `HumanInTheLoopMiddleware`: every tool call pauses for review, and `check_stock` (an `InterruptOnConfig`, so PyCharm type-checks it against the `TypedDict`) allows only approve/reject. The agent has an `InMemorySaver` checkpointer and `SmartAgent.config` carries a `thread_id`, so `chat()` sends only the new message, loops on `result["__interrupt__"]`, and resumes with `Command(resume={"decisions": [...]})`, one decision per pending tool call. `history()` reads the thread's messages from `get_state()`, and `reset()` switches to a new `thread_id`. `ask_human()` reads decisions from stdin, so pipe answers in to run it non-interactively. `chapter08_middleware/pii.py` stacks `PIIMiddleware` rules with `apply_to_input=True` (email `redact`, credit_card `mask`, url `hash`, mac_address `mask`, ip `block`) and pretty-prints the conversation to show the rewritten input. The built-in detectors only match a Luhn-valid card number and a 6-group MAC address, so keep test inputs valid. `block` raises `PIIDetectionError` instead of rewriting; the input contains `192.168.1.1`, so the run stops before the model call and the script catches the error and prints `e.pii_type` and `e.matches`. Remove the IP line to see the redacted conversation instead. The `test*.py` files in chapter01 and chapter02 are demos too; PyCharm runs them under pytest by default, which only imports them.
